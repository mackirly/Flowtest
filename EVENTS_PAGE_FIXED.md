# Исправления страницы События

## Проблемы
1. API не работало - использовались моковые данные
2. Календарь не отображался (хотя код был правильный)
3. В хедере не отображались проекты, аватар и имя пользователя

## Решения

### 1. Создан API клиент для событий
Файл: `/frontend/js/api/events_api.js`
- Методы для работы с событиями (CRUD операции)
- Метод для получения событий за конкретный месяц
- Поддержка пагинации

### 2. Обновлена страница events.js
- Импортированы реальные API клиенты
- `loadEvents()` теперь загружает события из API
- `loadTestCases()` загружает тест-кейсы из выбранного проекта
- Правильная обработка ошибок и пустых ответов

### 3. Исправлен хедер
- Удален статичный HTML хедера
- Добавлен placeholder для динамического хедера
- Подключен `app.js` который инициализирует хедер с:
  - Селектором проектов
  - Информацией о пользователе (аватар, имя)
  - Уведомлениями
  - Меню пользователя

### 4. Структура скриптов
Правильный порядок подключения:
1. Toast, i18n, utilities
2. `app.js` - инициализация хедера и общих компонентов
3. `events.js` - логика страницы событий
4. `init-auth.js` - проверка авторизации

## Что теперь работает

1. **Хедер**: 
   - Отображается селектор проектов с реальными данными
   - Показывается аватар и имя пользователя
   - Работает меню пользователя

2. **Календарь**:
   - Отображается корректно
   - Загружает события из API для текущего месяца
   - Поддерживает навигацию между месяцами

3. **События**:
   - Загружаются из API вместо моковых данных
   - Правильно обрабатываются ошибки
   - Поддерживается пагинация

4. **Тест-кейсы**:
   - Загружаются из текущего проекта
   - Используются для создания событий с тестами

## Примечания

- Если нет событий в БД, календарь будет пустым (это нормально)
- API endpoints: `/api/events/events/`
- Поддерживаются фильтры по датам: `date_from`, `date_to`
