# История запусков тестов - как это работает

## Текущая реализация

### 1. Автоматическое обновление истории

История запусков обновляется автоматически в следующих случаях:

1. **После завершения теста** (строки 1980-1985 в test-cases.js):
   - Когда тест завершается (статус: passed, failed, error, skipped)
   - Проверяется, активна ли вкладка "История запусков"
   - Если активна - история перезагружается автоматически

2. **При переключении на вкладку** (строки 2437-2440 в test-cases.js):
   - Метод `switchTab('history')` автоматически загружает историю
   - Используется ID текущего тест-кейса из `this.currentTestCase`

### 2. Симуляция vs Реальное выполнение

В системе есть два режима выполнения тестов:

#### Симуляция (фейковые данные)
- Используется когда:
  - Тест-кейс типа "manual" (ручной)
  - Нет привязки к automation_project
  - Нет automation_test_name
  - Произошла ошибка при запуске реального теста

- Что происходит:
  - Задержка 3 секунды (имитация выполнения)
  - Случайный результат: 75% успех, 25% провал
  - Генерируется фейковое сообщение о результате

#### Реальное выполнение
- Используется когда:
  - Тест-кейс типа "automated"
  - Есть привязка к automation_project
  - Указан automation_test_name
  - Найден соответствующий AutomationTest

- Что происходит:
  - Запускается реальный тест через execute_automation_test
  - Результаты реальные из тестового фреймворка

### 3. Почему данные могут казаться фейковыми

1. **Большинство тестов в симуляции**: Если у ваших тест-кейсов нет настроенной автоматизации, они всегда будут выполняться в режиме симуляции.

2. **Случайные результаты**: Симуляция использует random.choice для определения успеха/провала, поэтому результаты меняются случайно.

3. **Одинаковое время выполнения**: Все симулированные тесты выполняются ровно 3 секунды.

### 4. Как проверить, что история обновляется

1. Запустите тест
2. Дождитесь завершения (прогресс-бар покажет результат)
3. Если вкладка "История запусков" активна - она обновится автоматически
4. Если нет - переключитесь на неё, и история загрузится с новым запуском

### 5. Отладочная информация

Добавлено логирование в simulate_test_execution:
- Выводится информация о типе теста
- Показывается наличие automation_project и automation_test_name
- Это поможет понять, почему тест запускается в режиме симуляции

## Рекомендации

1. **Для реальных тестов**: Настройте automation_project и automation_test_name
2. **Для отладки**: Проверьте логи Celery worker для сообщений [SIMULATION]
3. **Для проверки обновлений**: Откройте консоль браузера и следите за сообщениями:
   - `[TestCases] History tab is active, reloading test runs...`
   - `[TestCases] Loading test run history for test case: <ID>`
