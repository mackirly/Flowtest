# Исправление проблемы с обновлением истории запусков

## Проблема
История запусков не обновлялась после выполнения тестов, хотя тесты выполнялись успешно.

## Причина
1. **API работает корректно** - запрос `/api/projects/{project_id}/test-cases/{test_case_id}/test_runs/` возвращает полную историю запусков
2. **Новые запуски создаются** - но некоторые остаются в статусе "pending" и не запускаются через Celery
3. **Фронтенд загружает историю** - но только при переключении на вкладку или если вкладка уже активна

## Найденные проблемы

### 1. Незавершенные запуски
В базе данных накопились запуски со статусом "pending" которые не были обработаны Celery:
- Run ID 4, 5, 6, 7 - все со статусом "pending", started_at = null

### 2. Логирование показало
- Последний успешный запуск был ID 36 в 10:06:23
- Celery обработал его корректно (видно в логах [SIMULATION])
- Automation project = None, поэтому используется симуляция

## Решения

### 1. Очистка pending запусков
```bash
docker-compose exec backend python manage.py shell -c \
  "from testcases.models import TestRun; \
   TestRun.objects.filter(status='pending', started_at__isnull=True).delete()"
```

### 2. Добавлена кнопка "Обновить" 
В UI на вкладке "История запусков" для ручного обновления

### 3. Улучшено логирование
Добавлены подробные логи для отладки:
- При проверке активности вкладки истории
- При вызове API для загрузки истории
- При обработке ответа от API

## Как проверить, что история обновляется

1. **Автоматически после теста**:
   - Откройте вкладку "История запусков"
   - Запустите тест
   - После завершения (когда прогресс-бар показывает результат) история должна обновиться
   - В консоли должны быть логи: `[TestCases] History tab is active, reloading test runs...`

2. **При переключении на вкладку**:
   - Запустите тест на вкладке "Детали"
   - После завершения переключитесь на "История запусков"
   - История загрузится автоматически с новым запуском

3. **Вручную**:
   - Нажмите кнопку "Обновить" на вкладке истории

## Возможные причины будущих проблем

1. **Celery не обрабатывает задачи**:
   - Проверьте: `docker-compose logs celery_worker`
   - Перезапустите: `docker-compose restart celery_worker`

2. **База данных заполнена pending запусками**:
   - Используйте команду очистки выше

3. **Проблемы с правами доступа**:
   - Убедитесь, что пользователь является членом проекта
